# Приём заявок: Cloudflare Worker → MAX + e-mail

Форма на сайте (`index.html`, блок `#zayavka`) отправляет JSON на этот воркер.
Воркер проверяет данные, отсекает спам и отправляет заявку в MAX Bot API,
дублируя её письмом. Токены живут только в переменных окружения Cloudflare —
в репозитории их нет и быть не должно.

## Что нужно от владельца сайта

| Переменная | Тип | Где взять |
|---|---|---|
| `MAX_BOT_TOKEN` | секрет | «MAX для партнёров» → Чат-боты → ⋮ → Настройки → токен |
| `MAX_USER_ID` | переменная | ID вашего профиля в MAX, куда бот шлёт заявки (см. ниже) |
| `RESEND_API_KEY` | секрет | resend.com → API Keys |
| `LEAD_EMAIL` | переменная | адрес, куда дублировать заявки |
| `MAIL_FROM` | переменная | подтверждённый в Resend отправитель, например `site@ваш-домен.ru` |
| `ALLOWED_ORIGINS` | переменная | `https://askuyr.github.io` (можно несколько через запятую) |

### 1. Регистрация бота в MAX

1. Откройте платформу «MAX для партнёров» (`https://dev.max.ru`) и подключитесь к ней. Подключение доступно юрлицам, ИП и самозанятым — резидентам РФ, поэтому нужен профиль организации/ИП и его верификация.
2. Создайте чат-бота, пройдите модерацию.
3. Откройте «Чат-боты» → нужный бот → **⋮ → Настройки** → скопируйте токен. Это значение `MAX_BOT_TOKEN`.
4. Запустите бота и напишите ему любое сообщение из своего аккаунта MAX.

### 2. Как узнать `MAX_USER_ID`

Пока бот не подписан на webhook, можно прочитать обновления long polling-ом:

```bash
curl -X GET "https://platform-api2.max.ru/updates" \
  -H "Authorization: ВАШ_ТОКЕН"
```

В ответе найдите событие `message_created` — ваше сообщение боту. `message.sender.user_id` и есть `MAX_USER_ID`.

Альтернатива: отправить заявку тестовым запросом и посмотреть, что вернёт API.

### 3. Деплой воркера

```bash
cd worker
npm install -g wrangler        # если wrangler ещё не установлен
wrangler login
wrangler secret put MAX_BOT_TOKEN
wrangler secret put RESEND_API_KEY
wrangler deploy
```

После `deploy` wrangler выведет адрес вида
`https://chigirin-lead.<account>.workers.dev`.

Проверка:

```bash
curl -X POST "https://chigirin-lead.<account>.workers.dev/api/lead" \
  -H "Content-Type: application/json" \
  -d '{"name":"Тест","phone":"+79210000000","email":"","message":"Проверка формы","consent":true}'
```

Ожидаемый ответ: `{"ok":true,"delivered":["max","email"]}`.

### 4. Подключение формы на сайте

В `assets/app.js` заполните константу:

```js
const FORM_ENDPOINT = 'https://chigirin-lead.<account>.workers.dev/api/lead';
```

Пока константа пустая, форма не отправляет данные и показывает сообщение
с телефоном — заявки не теряются молча.

### 5. Что уже реализовано в воркере

- проверка полей на сервере (имя, телефон, e-mail, согласие);
- honeypot-поле `company` — заполненные заявки тихо отбрасываются;
- ограничение частоты: один запрос с IP раз в 45 секунд (Cloudflare Cache API);
- CORS только для разрешённых origin;
- доставка в MAX и на e-mail; успех фиксируется, если сработал хотя бы один канал;
- ответ 502 со списком каналов, если не сработал ни один.

## Если MAX Bot API недоступен

Воркер продолжит работать в режиме «только e-mail»: достаточно не задавать
`MAX_BOT_TOKEN`. Если и Resend не подходит, замените `sendToEmail` на вызов
Formspree/Getform — остальной код менять не нужно.
